     9→     9→## 1. WHAT THIS PROJECT IS
    10→    10→
    11→    11→This is a **BusinessVance** management platform consisting of two parts:
    12→    12→
    13→    13→1. **Next.js 16 Admin Panel** (`/` route) — A functional admin panel that mirrors the WordPress plugin admin. Used for preview and development.
    14→    14→2. **WordPress Plugin** (`businessvance-services-manager/`) — The actual production-ready WordPress plugin (PHP).
    15→    15→3. **Client Portal** (`/client-portal` route) — A standalone client-facing page where clients can manage their projects, sign agreements, fill questionnaires, and upload documents.
    16→    16→
    17→    17→**The WordPress plugin is the production target.** The Next.js app is a reference prototype.

   275→   275→## 6. ADMIN PANEL (page.tsx) — 9 TABS
   276→   276→
   277→   277→`src/app/page.tsx` is ~1406 lines, monolithic (all types, components, state inline).
   278→   278→
   279→   279→### Architecture
   280→   280→- **All types defined inline**: Settings, CategoryItem, ServiceItem, PlanItem, IconItem, TabId
   281→   281→- **Helper components inline**: SortableRow, CopyBtn, SettingsCard, FormField, ColorField, Toast, BvIcon
   282→   282→- **Uses QuestionnaireBuilder and AgreementBuilder** from `src/components/admin/`
   283→   283→- **Uses ProjectsTab** from `src/components/admin/projects-tab.tsx`
   284→   284→- **No external component imports** beyond shadcn/ui, lucide-react, and the 3 admin components above
   285→   285→
   286→   286→### The 9 Tabs
   287→   287→
   288→   288→1. **Dashboard** — Stat cards (total services, plans, projects, active projects, completed, revenue), quick links to Projects and Client Portal, Quick Start guide
   289→   289→2. **Services** — Sortable table with drag handles, category dots, prices, visibility/featured toggles. Modal form: name, description, shortDescription, price, icon (dropdown from DB), turnaround days, button type/label/url, WC product ID, category, questionnaire template, agreement template, required documents (JSON editor), visible, featured
   290→   290→3. **Subscription Plans** — Sortable table with color swatches. Modal: name, subtitle, price, color picker, button label, WC product ID, category, visible, featured, dynamic features list (add/remove)
   291→   291→4. **Categories** — Table with name, slug (auto-generated), color swatch, service/plan counts. Edit modal
   292→   292→5. **Icon Manager** — Table with live SVG preview, name, label, category badge. Add/edit modal: name (slug), label, category dropdown (7 categories), SVG path textarea with live preview. Full CRUD
   293→   293→6. **Questionnaires** — Full questionnaire builder component (`src/components/admin/questionnaire-builder.tsx`, 942 lines). Create/edit/delete templates with sections and questions. Supports 13 question types, drag-reorder, conditional logic, shared sections
   294→   294→7. **Agreements** — Agreement template builder (`src/components/admin/agreement-builder.tsx`, 505 lines). Create/edit/delete templates with HTML content editor, preview mode, service linking
   295→   295→8. **Projects** — Project management tab (`src/components/admin/projects-tab.tsx`, 1113 lines). Create projects, view details, manage agreements, questionnaires, documents, status transitions, internal notes
   296→   296→9. **Settings** — 8 grouped cards: Branding, Colors, Services, Plans, Currency, Footer, Trust Badges, Layout. Logo upload, all brand colors configurable
   297→   297→
   298→   298→### Key Patterns
   299→   299→- **Icons are 100% dynamic** — loaded from DB via `/api/icons`, stored in `iconMap` (Record<name, svgPath>), used by `BvIcon` component everywhere

   301→   301→- **Toast notifications** via custom `Toast` component in page.tsx (not sonner)
   302→   302→- **All forms** use controlled components with `Record<string, unknown>` state

   306→   306→- Gold accent: #D4AF37 for primary buttons

   523→   523→## 14. IMPORTANT RULES FOR AI AGENTS
   524→   524→
   525→   525→1. **Two visible routes**: `/` (admin, 9 tabs) and `/client-portal` (standalone client page)
   526→   526→2. **Port 3000 only** — Dev server runs on port 3000. Never use other ports for the Next.js app.
   527→   527→3. **Use API routes** — All backend logic goes in `src/app/api/`, NOT server actions.
   528→   528→4. **z-ai-web-dev-sdk** — MUST be used in backend only, never client-side.
   529→   529→5. **No indigo/blue** unless user requests it.
   530→   530→6. **shadcn/ui** — Use existing components in `src/components/ui/`. Don't build from scratch.
   531→   531→7. **Don't remove dynamic functionality** — Icons, settings, and data are all dynamic from the database.
   532→   532→8. **Page.tsx is monolithic** — All admin UI is in one file with inline helper components.
   533→   533→9. **Sticky footer** — If footer exists, it must stick to bottom on short pages.
   534→   534→10. **Browser verify** — After making changes, verify in the Preview Panel (not localhost URL).
   535→   535→11. **ESLint** — Run `bun run lint` to check. Config is very permissive (most rules off).
   536→   536→12. **Phase 2 core modules exist** but are NOT yet used by existing API routes. They're ready to be wired in.
   537→   537→13. **Client Portal is separate** — It's at `/client-portal`, NOT a tab in admin. The old `src/components/admin/client-portal.tsx` still exists but is NOT imported anywhere.
   538→   538→14. **Don't modify shadcn/ui components** in `src/components/ui/`.
   539→   539→15. **Use `use client`** directive for all interactive components.
